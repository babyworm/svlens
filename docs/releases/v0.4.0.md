# svlens v0.4.0 release notes

Minor release over v0.3.6. It adds new user-facing surfaces (synthesizability
check, user-defined name rules, inline waivers, Python API, VS Code extension,
SARIF/PR-summary conversion), deepens connectivity and CDC analysis, and adds
reproducible OpenTitan benchmark evidence. svlens remains a **pre-signoff
structural analysis** tool; none of the additions below is a sign-off proof.

## New features

* **`svlens conn --check-synth`** -- flags constructs that synthesis turns
  into latches or memories even when Verilator `-Wall` is clean. A
  variable-index partial write of an unpacked array in a clocked block that is
  read combinationally is an `ERROR` (non-zero exit); an `always_comb` signal
  assigned on only some branches is a `WARN`.
* **`--user-rules <yaml>`** (`conn` and `all`) -- YAML name-pattern checkers
  for modules, instances, signals, and ports, with IDs, severities, JSON
  output, and waiver support. See [`docs/user-rules.md`](../user-rules.md).
* **Inline waivers** -- a scoped `// svlens: waive ... reason: ...` source
  comment for conn issues and CDC crossings (CDC requires a destination FF
  path).
* **Python API** -- installable, CLI-backed `svlens.conn`, `cdc`, `metrics`,
  and `all_modes` functions that return the parsed JSON reports.
* **VS Code extension** (`vscode/`) -- runs conn/CDC on demand and shows
  source-located findings as editor diagnostics.
* **Report conversion** -- `scripts/report_convert.py` turns reports into
  SARIF and a PR summary. See
  [`docs/report-integration.md`](../report-integration.md).
* **`svlens all` cross-references** -- `svlens_summary.json` links conn issues
  and CDC crossings that share an exact signal path, when both formats write
  JSON in the current run.

## Analysis depth

* **Connectivity** -- every edge is labeled `direct` or `approximate`.
  Ordinal bit ranges are kept through constant/indexed part-selects,
  constant-indexed array elements, packed-array fields, concatenations (up to
  4,096 bits), size casts, and simple `always_comb` copies. Modport and
  whole-interface members are tracked per signal. Enum values and parameters
  are now treated as tie-offs, so a shared constant no longer creates a path
  between unrelated instances. Unmapped positional assignments are counted as
  bit-flow gaps.
* **CDC** -- SDC periods (including generated-clock chains),
  `set_false_path`, `set_max_delay`, and exclusive clock groups are reported
  as timing context without downgrading a crossing. JSON adds root-clock
  provenance, `reset_usage` (driver FF, polarity, conditional reset muxes),
  capture conditions, and recommendations that distinguish single-bit level,
  event, and multi-bit bus transfers. `--format html` writes a CDC crossing
  explorer.
* **SVA** -- `--emit-sva` now also emits stage-transfer assertions for unguarded
  2FF/3FF chains plus contracts for verified `prim_fifo_async`,
  `prim_sync_reqack`, and `prim_sync_reqack_data` instances, each linked to
  its crossing in JSON. An optional `make test-sva-sim` (Verilator) shows the
  generated properties fire on mutated fixtures.
* **Metrics** -- roots report maximum fanout and an uncalibrated
  operator-weighted `gate_cost_proxy`.

## Fixes

* **CDC: abort on real designs in assert-enabled builds** -- resolving a CDC
  source through a continuous assign dropped the ancestor port chain. Builds
  with asserts enabled (`make build` sets no `CMAKE_BUILD_TYPE`) aborted on
  every OpenTitan target; NDEBUG builds silently missed sources more than one
  port level up behind a local assign. On the pinned OpenTitan SoC this adds
  one CAUTION crossing (243 -> 244 records); see the
  [2026-10-08 benchmark follow-up](../benchmarks/opentitan-2026-10-08.md).
* **CDC: crossings hidden behind a top-level alias** -- a child output that
  reached another child's input through `assign w2 = w1;` (or a chain of
  such aliases) in the parent was not traced, so the crossing was silently
  missed. Pure single-signal aliases are now followed; computed right-hand
  sides remain unresolved.
* **`svlens all` cross-references** no longer read stale JSON reports left in
  a reused output directory when the current run writes non-JSON formats.
* **VS Code** clears diagnostics from an earlier run when a later run fails.

## Benchmark evidence

`bench/opentitan` is extended with pinned OpenTitan AES and full-SoC runs, a
source-derived oracle (358/358 direct sibling-port paths in seven selected IP
scopes), checked path and absent-path probes, and a deterministic 20-row
connection sample. These are bounded checks, not whole-design precision or
recall. See [`docs/benchmarks/opentitan-2026-10-08.md`](../benchmarks/opentitan-2026-10-08.md).
The scheduled/on-demand `opentitan-benchmark` workflow now completes in
GitHub Actions (assert-enabled build) with every gated reference passing.

## CI and test infrastructure

* New jobs: AddressSanitizer (with a separately built non-mimalloc slang),
  Python wheel, and VS Code extension checks; a scheduled OpenTitan
  benchmark workflow.
* apt installs are time-bounded and retried, and every job has
  `timeout-minutes`, so a stalled mirror can no longer hold a run for 6 hours.
* Per-OS portability checks (Ubuntu/macOS) moved to `portability.yml`, which
  runs on `v*` tags or manual dispatch.
* `format-check` prints its violations instead of failing silently.
* Parallel CTest fixture races (filelist, CDC, SDC, waiver temp files) are
  fixed, and the reset/SDC detection tests that had been downgraded to
  warnings are hard assertions again.

## Schema changes

All four JSON schemas gained fields; existing fields keep their meaning. See
[`docs/schema/`](../schema/) -- notably `connections[*]` edge labels and
bit-flow gaps in `connect_report`, timing/reset/SVA fields in `cdc_report`,
`max_fanout` / `gate_cost_proxy` in `metrics_report`, and
`cross_reference_status` / `cross_references` in `svlens_summary`.

## Test count

`ctest` reports **743/743 passing** in a local default build. CI runs the
same suite in its build, coverage, and AddressSanitizer jobs.

## Migration notes

* JSON consumers should tolerate the added fields.
* `--check-synth` errors make `svlens conn` exit non-zero; it is opt-in.
* The per-OS portability jobs no longer run on every push; trigger
  `portability` manually when a change touches platform-specific code.

## Known follow-ups

See [`docs/design/feature-roadmap.md`](../design/feature-roadmap.md). Open
items include generic handshake/FIFO SVA, full branch-sensitive dataflow,
reset-domain-crossing analysis, gate-cost calibration, in-process pybind11
bindings, and VS Code Marketplace publishing. An unsynchronized crossing
whose only intervening logic is a pure `assign` alias is still classified
`CAUTION` / `Ac_cdc02` (glitch risk) rather than `VIOLATION`.
